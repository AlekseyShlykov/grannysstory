## Поведение supervisor

- Сохраняет cwd, использует существующую аутентификацию ChatGPT, отказывается от API overrides. Не меняет модель, аккаунт или sandbox policy; workspace-write и approval never означают остановку недоступных действий, без обхода политик.
- Параметры одного дочернего вызова `forced_login_method="chatgpt"` и `model_provider="openai"` запрещают подмену способа входа/провайдера. Они не переписывают config.toml. Параметры сверены с установленным CLI и [официальным справочником конфигурации](https://developers.openai.com/codex/config-reference).
- Только JSON error/turn.failed с явным usage-limit кодом или точной фразой CLI о исчерпанном allowance разрешают повтор. HTTP 429, rate_limit, сеть, авторизация, разрешения, model_not_found и остальные ошибки останавливают процесс.
- Если error содержит числовой Unix `resets_at`, ждёт до него плюс две минуты. Иначе интервалы 30/60/120 минут, максимум четыре попытки по умолчанию. Не угадывает время по тексту.
- Удерживает flock; второй supervisor той же задачи не стартует. Ctrl-C/SIGTERM останавливает дочерний процесс; принудительное завершение предусмотрено только для не отвечающего дочернего процесса после десяти секунд. Состояние и файловая блокировка сохраняют возможность ручного перезапуска.
- Журнал содержит только время, номер попытки, класс исхода и код возврата; stdout/stderr, токены и ответы модели не сохраняются. Сеансы продолжает штатный CLI, прогресс проекта хранится в research_progress/.
- После успешного turn процесс заканчивается. Если работа осталась, это видно в tasks.json, и нужен следующий ручной запуск; это не безусловный цикл запросов. Сон компьютера, выключение и завершение терминала не считаются автоматической фоновой службой.

Для длительного запуска в терминале можно использовать привычный менеджер процессов пользователя. Здесь launchd/cron не устанавливались.

Проверки процесса с локальным имитатором CLI: остановка на model_not_found, один ограниченный quota attempt, отказ второму supervisor при удержанном flock, SIGTERM дочернего процесса и ручной перезапуск. Это проверка механики supervisor без модели и без смены авторизации; она не снимает блокер настоящего CLI.
