# Бриф исследователя страны

Проект — браузерная narrative-игра «Бабушка»: игрок слушает воспоминания сгенерированной пожилой женщины. Исторические записи определяют, какие условия и события *могли* окружать её в данном месте и году. Они не утверждают, что событие случилось с ней лично. Прочитайте `data/SCHEMA.md` целиком до начала работы.

## Главные правила

1. **Ничего не выдумывать.** Каждое событие и контекстная запись с `verification_status: "verified"` опирается минимум на одну страницу, которую вы *реально открыли в этой сессии* (WebFetch). URL этой страницы идёт в `evidence[].url`, дата доступа `2026-10-29`. Если страница не открылась или не подтвердила утверждение, запись не создаётся (или получает `needs_review` с пояснением в `research-notes`). Никогда не записывайте факт «по памяти», а затем подставляйте правдоподобный URL.
2. **Источники.** Приоритет: официальная статистика и госорганы, архивы, национальные библиотеки, музеи, университеты, муниципалитеты, энциклопедии (Britannica, Larousse, БРЭ, PWN). Wikipedia допустима как вторичный источник с `confidence: "medium"`; если удалось подтвердить первичным/официальным — `high`. Каждый использованный сайт зарегистрирован в `data/sources/<cc>.json` (схема в SCHEMA.md) с лицензией/условиями, как вы их поняли. Зарегистрируйте и те приоритетные архивы, которые не удалось использовать (`status: "inaccessible"` или `"catalogued"`, причина в `notes`). Не обходите paywall, авторизацию, капчи; не скрейпьте массово; соблюдайте условия сайтов. Не отправляйте никаких персональных данных (email и т. п.) в запросах.
3. **Свои слова, по-русски.** `title` и `historical_summary` — краткий собственный пересказ на русском (1–3 предложения). `title_original` — необязательное название на языке страны. Не копировать газетные тексты, транскрипты, дневники. Не упоминать бабушку/героиню в исторических полях: личные возможности только в `narrative_hooks` / `potential_impacts`.
4. **Даты.** Точность строго как в источнике (`YYYY`, `YYYY-MM`, `YYYY-MM-DD` = `year`/`month`/`day`). Дата газетной публикации ≠ дата события. Неточная дата — `approximate: true`.
5. **География.** Городское событие привязывается к городу (`municipal`), областное — к региону, национальное — к государству. Не дублируйте национальное событие в городских записях. Событие относится только к тем местам, где оно реально происходило или действовало.
6. **Не только войны.** Распределите записи по эпохам 1900–1919, 1920–39, 1940–59, 1960–79, 1980–99, 2000–09, 2010–19, 2020–25. Поздние десятилетия так же важны: телевидение, бытовая техника, авиаперелёты, компьютеры, интернет, мобильная связь, пандемия COVID-19, закрытие и открытие предприятий, транспорт, жильё. Приоритет — то, что меняло обычную жизнь: работа, закрытия заводов, забастовки, наводнения, транспорт, школы, больницы, университеты, жильё, здравоохранение, семейное право, права женщин, культура и досуг. Местная политическая мелочь — низкий приоритет.
7. **Чувствительное.** Репрессии, массовая гибель, преследования, насилие — `sensitive: true`. Персональные данные живых людей не собирать; для современных периодов только агрегаты.
8. **Статистика в контекстах** — с годом, единицей, областью (`area_id`), определением населения и методом. Популяционная статистика — не правило для личности.

## Объём и порядок

Ориентир для страны: 250 событий и 125 контекстных записей, но это цель, не квота: проверенность важнее количества. Реалистичный порядок работы:

1. Создайте иерархию мест (`data/locations/<cc>.json`) для пяти целевых мест с историческими административными изменениями и датами. Координаты берите из Wikidata (страница `https://www.wikidata.org/wiki/Special:EntityData/Q….json`) или оставьте `null` — их потом сверит сборщик. Укажите QID для каждого узла, где вы его проверили.
2. Национальные события по всем эпохам (около 60–80).
3. Региональные и городские события: по 15–30 на каждое целевое место, если есть надёжные источники. Где их нет — зафиксируйте пробел, не заполняйте выдумкой.
4. Контексты повседневной жизни: национальные по десятилетиям (жильё, техника, транспорт, связь, работа женщин, брак/развод/рождаемость/бездетность, образование, зарплаты/цены, здравоохранение, досуг), затем региональные/городские, где есть данные.

**Сохраняйте файлы постепенно** (после каждых ~10 записей) и регулярно запускайте:

```bash
python3 scripts/historical-data/validate/validate.py --country <CC> --quiet-warnings
```

К концу в ваших файлах должно быть 0 ошибок. Просмотрите и предупреждения.

## Файлы — только свои

Пишите только в:
- `data/locations/<cc>.json`
- `data/sources/<cc>.json`
- `data/historical/<country>/national/*.json`, `regions/*.json`, `cities/*.json` (формат `{"records": [...]}`)
- `data/contexts/<country>/*.json` (формат `{"records": [...]}`)
- `data/research-notes/<cc>.md`

Не трогайте чужие файлы, `data/locations/common.json`, `content/`, `src/`, `scripts/`, `public/`. Не запускайте npm. Если нужен общий узел (`world`, `fr`, `us`, `gb`, `gb-eng`, `pl`, `ru`, `su`, `ru-empire`) — он уже есть в `common.json`; если нужен другой общий узел, создайте `state-…` у себя и напишите об этом в итоговом отчёте.

ID событий: `<cc>-<место или nat>-<год>-<краткий-слаг>`, например `fr-lyon-1978-…`, `pl-nat-1956-…`. ID контекстов: `<cc>-ctx-<…>`. ID источников: `<cc>_<краткое_имя>`.

## research-notes/<cc>.md

Кратко: какие источники реально использованы, какие не удалось (почему), ограничения лицензий, пробелы по местам и эпохам, спорные места, итоговые фактические количества записей (по места́м и эпохам). Без преувеличений: если что-то не проверено, так и напишите.

## Итоговый ответ

Коротко (до 300 слов): фактические количества событий/контекстов по местам и эпохам, число ошибок валидатора в ваших файлах, главные пробелы, созданные `state-…` узлы, любые сомнения в данных.
