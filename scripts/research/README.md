# Продолжаемое историческое исследование

Рабочая область: шесть стран, 18 городов, события и контексты 1900–2020. Основные правила: `AGENTS.md`, `PROJECT.md`, `DIALOGUE_BIBLE.md`; состояние — `research_progress/`. Наличие источника в каталоге не означает чтение документа.

## Порядок нового batch

1. Прочитать прогресс и соответствующие авторские файлы. Сверить стабильные ID и уже извлечённые утверждения.
2. Открыть конкретный документ обычным разрешённым способом. Проверить условия просмотра, загрузки и использования. Не обходить 403, CAPTCHA или ограничения коллекции. Не считать поиск, каталог или титульный лист достаточным доказательством содержания.
3. Сохранить документальный источник через `records.source`. Указать репозиторий, точный URL, язык, дату доступа, прочитанные страницы, ограничения и перекос источника. Это атомарно обновляет реестр и checkpoint страны. Для display-only коллекций доступны параметры `rights` и `restrictions`.
4. Создать `evidence` с названием, идентификатором, датой документа (или явно неизвестной датой), страницей и точным поддерживаемым утверждением. `is_primary` относится к данному утверждению: решение суда первично для своего решения, его историческая справка может быть вторичной. `claim_coverage: partial` не входит в числитель полной первичной опоры.
5. Записать собственный пересказ через `event`/`context` и `save_batch`. Использовать существующие `CATEGORIES`, `CONTEXT_TYPES`, `SCOPES`. Не дублировать национальные события по городам. Отдельно сохранять единицы, границы, население, методику и версию статистики. Не выводить личную биографию из городских чисел.
6. Повторный запуск должен сохранять одинаковые записи и отклонять конфликтующие. У helper нет режима молчаливого перезаписывания. Исправление сначала сравнивается с прежним утверждением и источниками, затем явно вносится атомарно.
7. Выполнить конвейер, проверки и обновить STATUS/COMPLETED/ERRORS. При незавершённой полноте оставить `researching`, `researchOnly` и задачи исследований открытыми.

`batches/*.py` — воспроизводимые извлечения из уже прочитанных оригиналов с фиксированной датой доступа; они не заменяют чтение и не скрейпят архивы. Повтор не скачивает документы и не требует внешнего API. Для ранее собранных записей источником истины служат авторские JSON и checkpoints страны.

## Проверки и экспорт

```bash
python3 scripts/historical-data/validate/validate.py
npm run data:world
npm run test:research
npm run typecheck
npm test -- --reporter=dot
npm run build:pages
```

После успешного SQLite → JSON экспорта автоматически сохраняются хэши SQLite/манифеста и точные ID в `research_progress/exports/latest.json` и `countries/*.json`. Авторские данные старых стран сверяются с BASELINE.json. Это исследовательская контрольная точка, не сертификат готовой страны. Отчёт долей: `npm run research:report`.

Если Vitest запущен после появления новых JSON и сообщает, что manifest pack отсутствует только в `import.meta.glob`, выполнить `npx vitest --clearCache`, затем повторить тесты. Не маскировать реальное отсутствие пакета ослаблением проверки.

Исследовательские пакеты не предлагаются для старта или миграции. Новые переводы загружаются с пакетом места; IndexedDB различает обновления по SHA-256 манифеста. Формат сохранённой жизни не сбрасывается. Человеческая литературная рецензия остаётся OPEN по существующему временному правилу D-019; автоматические проверки и авторская вычитка агента не выдаются за эту рецензию. Текущие ограничения каждой страны указываются в её отчёте.
