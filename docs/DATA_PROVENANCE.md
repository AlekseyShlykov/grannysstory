# Происхождение данных

## Поток

`открытая страница источника → ручная сверка утверждения → запись sourceId → нормализованный JSON → автоматическая проверка → public/data`

Исторические записи не создаются сначала «по памяти» с последующим поиском ссылки. Пакет не публикуется, если запись не имеет зарегистрированного источника, корректной даты, географии, применимости и статуса `verified`.

## Классификация

- `VERIFIED_HISTORICAL` — проверенный внешний факт; обязан иметь `sourceId`.
- `DATA_DERIVED` — вывод из документированного датасета и метода. В текущем наборе таких записей нет.
- `FICTIONAL_PERSONAL` — оригинальное личное событие вымышленной героини. Не используется как доказательство исторического утверждения.

Сценарные веса генератора являются игровыми допущениями и не относятся к `DATA_DERIVED`.

## География и названия

Координаты пяти городов зафиксированы из Wikidata и используются только для локальной схематической проекции. Линия между точками не объявляется точным маршрутом. `placeId` остаётся постоянным, а отображаемое имя выбирается по году: Тверь / Калинин / Тверь, Петроград / Ленинград / Санкт-Петербург, Новгород / Великий Новгород.

## Ограничения

- Новгородская и Смоленская области представлены только областными центрами.
- Нет статистически рассчитанных вероятностей профессий, образования, эвакуации или семейных структур.
- Нет архивных материалов, разрешённых к воспроизведению в интерфейсе.
- Наличие URL подтверждает прослеживаемость, но не заменяет экспертную историческую рецензию. Центральные чувствительные утверждения перед публичным релизом требуют человеческой проверки специалистом.

## Проверка

`scripts/verify/historical-data.mjs` проверяет полноту источника, URL, статус, даты, географию, дубликаты, применимость, периоды названий и отсутствие неподтверждённых вероятностных полей. Он не способен доказать истинность содержания страницы и не заявляется как замена историка.

Во время новой игры браузер загружает только выбранный файл из `public/data/regions`, проверяет его регион и версию, затем сохраняет пакет в IndexedDB. Каноническое состояние жизни хранится отдельно. При отсутствии или повреждении пакета старт не продолжается, а интерфейс оставляет выбор доступным и показывает ошибку.
